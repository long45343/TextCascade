# living-document 技能视角的文档审查计划

## 任务

以 living-document 技能的五条写作规范为审查标准,审查项目内除 specs 目录外的全部文档,输出一份中文审查报告。报告本身也按该技能写成(连贯散文、克制的 Markdown),直接在对话中输出,不新建文件、不修改任何文档。既往 git 历史中评审报告文件曾被整体删除(REPO_ROAST_REPORT.md),故报告不落盘。

## 审查对象(6 份)

- README.md、README_ZH_CN.md(双语镜像)
- CHANGELOG.md(256 行,最大)
- Perf.md(双语性能报告)
- CONTRIBUTING.md
- docs/README.md(协议规范指针页)

排除:specs/(用户指定)、.trae/specs/(Trae IDE 工具产物)、LICENSE(法律文本)、.github/ 工作流配置。

## 审查标准与体裁豁免

技能五条原则逐份对照:连贯散文优先、Markdown 克制(加粗/斜体、列表使用时机)、图表规范(禁 ASCII art,应用 Mermaid)、无痕修订措辞、版本隔离。

判断式套用,以下豁免(报告会说明理由):
- CHANGELOG 的"改为/不再/迁移"是变更记录的事实本义,不按修订痕迹扣分;但"**加粗主题词**:"前缀习惯与碎片化问题仍按规范评估
- README 的版本溯源(Since/Before v2.0.0)是兼容性与致谢的功能性信息,豁免
- Perf.md 第 2 节的 dumpsys 原始输出属数据存档
- docs/README.md 的"为什么删除本地副本"是文档的真实主题,不是修订痕迹

## 执行步骤

1. 精读尚未完整读过的 CHANGELOG.md、Perf.md 剩余部分(README 双语版、CONTRIBUTING、docs/README 已核实完毕)。
2. 逐份形成发现:每处问题给出行号定位、技能条目依据、严重度、具体改法建议。
3. 横向汇总共性问题与整体印象,指出各文档与"连贯散文"标准的距离。
4. 以连贯散文 + 简单 ### 标题输出完整报告。

## 已预判的主要偏离点(报告时将精确定位)

- README 双语版:"Be different from ClipCascade"/"Features"/"Architecture" 三节的"加粗标签 - 短句"碎片列表;Unicode 箭头架构图(应转 Mermaid);加粗 11 处。
- CONTRIBUTING.md:通篇无上下文短句列表。
- Perf.md:数值加粗强调 14 处;表格后附解读散文是亮点。
- CHANGELOG.md:条目多为完整句,主要问题在加粗前缀习惯。
- docs/README.md:最接近规范,仅列表内加粗强调 6 处。
